The false green

A passing test can be lying to you.

The editor in the demo runs an async normalize pass after every input — a completely ordinary thing to do — but it mishandles the caret. Paste the whole string with fill() and the normalize runs once, after everything's in place: green. Type it a key at a time and the normalize fires between keystrokes, sending the caret to the start, so “hello world” lands as “dlrow olleh.”

Same code. Same assertion. The only difference is timing — and timing is exactly what instant-input tests throw away. Cadence puts it back.

Genuine key events

Every character is a real, trusted key press through the browser — not a value set or an insertText. Editors see input the way a person produces it.

Deterministic by seed

The same seed replays the exact same keystrokes and timing. A flake you catch in CI is a flake you can reproduce locally, on the first try.

Typing personas

Model a confident touch-typist, a two-finger hunter, or phone thumbs — each with its own speed, burst rhythm, and error profile.

Drop-in for Playwright

One function. Your existing tests.

# Playwright today
npm install -D @cadence/playwright playwright

// your spec — swap fill() for humanType()
import { humanType, personas } from '@cadence/playwright';

await humanType(page.locator('.editor'), 'The quick brown fox.', {
  ...personas.fastDev,
  typoRate: 0.05,   // real adjacent-key slips, self-corrected
  seed: 'ci-42',    // same keystrokes every run
});

Under the hood, the pure @cadence/engine turns text into a deterministic, timed keystroke stream — burst-and-pause rhythm, jitter, fatigue, self-correcting typos. A Cypress command is next.

Cadence is a working name for a repositioning of an existing typing engine toward honest, paying uses — testing rich-text editors and recording product demos. It is a product concept, not a registered company or a real service you can buy yet.
